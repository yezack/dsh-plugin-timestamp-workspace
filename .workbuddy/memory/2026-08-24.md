# 2026-08-24 dsh 插件工作日志

## dsh 无法启动修复（genui 重复 + 残留进程清理）

用户反馈 dsh 桌面应用又无法启动。日志根因：`duplicate loader entry id: genui`，插件树加载失败（code=1）。

**根因**：`~/.dsh/profiles/web/package.json` 的 `dependencies` 与 `dsh.profile.bundles` 里同时挂了两个 genui：
- `@omdsh-dev/dsh-genui`（github:omdsh-dev/dsh-genui 官方源）
- `@changfenhuang/dsh-genui`（gh-proxy.com 镜像，同一仓库固定 commit 38851ba）

两个包都向插件树注册 `genui` loader entry id → EntryGroup.update 报 duplicate → 整个 plugin tree 失败。

**修复**：
1. 备份 `package.json` → `package.json.bak-20260824-genui-fix`
2. dependencies 和 bundles 中移除 `@changfenhuang/dsh-genui`（保留官方 `@omdsh-dev/dsh-genui`）
3. `npx @deepseek-ai/dsh --profile web --dump-config` 验证：genui 只注册一次，timestamp-workspace/mcp-client/dsh-desktop 均正常
4. 清理残留进程：4 个 DeepSeek Harness.exe 崩溃壳 + 孤儿 dsh 服务 node.exe（PID 14360，占 3080）+ task-board stale 锁 `~/.dsh/task-board/ledger-v2.lock`（14360 持有，已删除）

**经验**：dsh profile 的 package.json 里同名仓库的不同安装源（官方 git + gh-proxy 镜像）会同时进 bundles 导致 loader entry id 重复。装插件前先查 `dsh.profile.bundles` 是否已有同名注册。dump-config 验证命令：`NODE_OPTIONS= ELECTRON_RUN_AS_NODE= npx --yes --prefer-offline @deepseek-ai/dsh --profile web --dump-config`。
